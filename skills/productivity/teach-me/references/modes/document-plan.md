# Document or plan lesson

Use for a PRD, RFC, implementation plan, architecture proposal, policy, or other decision document.

## Snapshot

Capture the exact document state used: canonical URL/path, title, author when relevant, revision/version/hash, and capture date. Runtime must not re-fetch and reinterpret it. Respect repository instructions and authentication boundaries while reading it.

## Lesson shape

Build a faithful model before critiquing it. Progress from problem and users to constraints, proposed system, state/data flow, rollout, risks, and open decisions. Link each visual claim to its source section.

Keep three layers visibly distinct:

- `document states`: what the document explicitly says;
- `inference`: consequences reasonably implied by it;
- `critique`: gaps, alternatives, contradictions, or risks raised by the teaching agent.

Use a system map, dependency graph, timeline, or state transition when it reduces prose. End with a checkable decision exercise: prioritize a risk from stable choices, repair an ordered gap, predict a downstream consequence, or choose between documented tradeoffs.
